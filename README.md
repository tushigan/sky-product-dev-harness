# SKY 产品开发经理（Codex / Claude Code 统一包）

**当前版本：v6.3 ｜ 发布日期：2026-10-20 ｜ 需要 Python 3.9+**

这是一套给 AI 编程助手（Codex 或 Claude Code）用的“产品开发框架”。装进一个项目文件夹后，助手会扮演一位产品经理，带着一个有想法、但没做过产品的人，把产品一步步做出来：先把需求问清楚写成文档，有界面就画几版设计稿让你选，再排成一个个阶段开发，每个阶段做完先自己检查一遍再给你看，最后按你的需要发布上线。顺序不是死的，中途加功能、改主意、先发一版给朋友看都可以。

- **给谁用**：想做一个网站、桌面软件、手机应用、命令行工具，或者规则与技能包这类本地文件包，但不懂技术的人；也适合想让 AI 按固定流程、留好文档和交接记录来开发的人。
- **它是什么**：一个文件夹，里面是规则（`AGENTS.md`）、6 个环节技能（拷问需求、设计、计划、开发、复核、发布）、2 个帮手（只读审查员、上网查证的探路员）和几个检查脚本。Codex 和 Claude Code 共用同一个文件夹，可以交替接着做。
- **它不是什么**：不是网页系统，不需要服务器、账号或密钥；不是给 Claude 网页聊天用的插件；包里不带任何具体项目的资料。

## 安装或更新：复制下面一段给你的 Agent

新项目先建一个空文件夹；已有项目就用原来的项目文件夹。在 Codex 或 Claude Code 里打开它，把下面这段整段贴进对话：

```text
请从 https://github.com/tushigan/sky-product-dev-harness 安装或更新“SKY 产品开发经理”开发框架到当前文件夹：先读取仓库根目录的《版本清单.json》和《给Agent的安装更新提示词.md》，再严格按其中流程执行——没装过就安装最新版；装过旧版就先备份再升级，我的需求文档、设计规范、开发计划、设计稿和代码一个字都不能改；已是最新版且检查通过就不重复覆盖。下载包要核对 SHA-256，装完跑包内检查并把实际结果告诉我；没有网络或 Python 就直说，不要声称完成。
```

首次安装和以后更新都用同一段。以后仓库发了新版本，再贴一次，Agent 会比对版本清单，判断要不要升级、只换框架部分。详细步骤见[给 Agent 的安装更新提示词](给Agent的安装更新提示词.md)。装好或升级后重新打开这个文件夹的对话，直接说“我想做……”或“继续开发”。

## 6.3 改了什么（白话）

- **动手改产品之前先过“三道门”**：不管改动大小、产品有没有界面（规则、技能包这类也算），你说“改”“都改”“全做”或批准一批改动后，Agent 在动第一个产品文件前，会先确认三件事——这些改动登记进了需求清单、排进了开发计划、问过你要不要开开发循环。缺哪样就先补哪样，补好、问完、你回答之后才动手。
- **“开发循环”那一行只记你的回答**：Agent 不能自己写“不需要”“未涉及”给自己开豁免。
- **叫停就停**：你直接说停，或从另一个对话转来停下的指示，它做完手上那一步就停；转来的指示只用来叫停，里面夹带的其他要求要先问你本人。
- **想先试试某个做法**：放在单独的“探路”文件夹里试，不算改产品，不用过门。
- **存档时自动提醒**：装好提交检查后，改到产品文件而三道门有缺口时会提醒，只提醒、不拦；也可以随时手动自查。
- 自带回归检查从 18 项增加到 22 项。经过两轮独立审查，第二轮通过；还没在真实项目里看 Agent 是否真的每次都先过三道门，Codex 那边没有实际试过。起因是一个项目里 Agent 听到“全做”就直接动手、没补文档也没问开发循环，这版就是补这个漏洞。

## 6.2 改了什么（白话）

- **新增“开发循环”**：以前要你每个项目都手动交代一遍“你规划和检查、代码派别人写、不过就返修”，现在框架自带。
- **开工前先问你**：开始写代码前，Agent 会问要不要开，并建议两档——**便宜档**（平时写代码和前两次返修用）和**聪明档**（返修两次还不过时用）。每档是一个模型加一个思考深度，你可以照建议，也可以自己改；以后随时可以说“关掉开发循环”或“换档”。
- **开了以后怎么跑**：Agent 自己只做规划和检查，代码交给它在背后派出的帮手写；检查不过就派新帮手只修检查出来的问题。便宜档修两次还不过，换聪明档再修一次；还不过才停下来问你要不要开更深的思考或换更强的模型，你定了以后它每多修一轮都会再问你，不会无限修下去。
- **一路做完**：一个阶段检查通过就接着做下一个，直到全部阶段做完、全盘检查过再交给你；中间每过一个阶段说一句进展。
- **该停照样停**：要上线、推送（把存档备份到网上）、花钱、对外发消息、删你的文件、要你登录或付钱、冒出新需求、检查里有要你拍板的事，都会停下来问你（你之前已经同意过的照旧办）。
- **断了能接上**：软件关掉后它不会在后台继续；下次打开说“继续开发”，会从记录的那一批接着做。
- 自带回归检查从 17 项增加到 18 项。经过两轮独立审查，第二轮通过；还没在真实项目里完整跑过一次开发循环，Codex 那边派帮手时指定模型只按官方文档查过、没有实际试过。

## 6.1.3 改了什么（白话）

- 只更正了包里一份验收说明里过时的一句话；规则、技能、工具和检查都没有变。6.1.2 的项目升上来只是换个版本号，也可以不升。

## 6.1.2 改了什么（白话）

- **跟你说话更好懂**：汇报和总结分三段——做了什么、对你有什么影响、要你做什么；正文里不夹命令、程序名和英文术语；要你复制的东西放在单独的框里，并说明贴到哪里。
- **交给另一个 Agent 接着做时三样一起给**：写好的提示词文件、一段能直接复制的短提示词、建议用什么模型和多高的思考等级。
- **可以“自动接力”**（6.2 起并入“开发循环”）：软件支持在背后派助手时，Agent 可以提议让助手做完一批、另一个助手核对、通过再做下一批；只有你同意才这样做，遇到要你拍板、上线、花钱、对外发消息、删文件时会停下来。
- **项目交接记录分成上下两半**：上半给你看，下半是给 Agent 的技术附录。
- 自带回归检查从 16 项增加到 17 项；修了一个 6.1.1 就有的老问题：项目里已经建好存档仓库、装好提交前检查时，回归检查以前必然有 1 项不过，现在都能全过。

完整版本记录见 [统一包/说明/版本记录.md](统一包/说明/版本记录.md)，包内使用说明见 [统一包/使用说明.md](统一包/使用说明.md)。

## 仓库里有什么

```text
README.md                     本页
给Agent的安装更新提示词.md     Agent 安装 / 更新的完整流程
版本清单.json                  当前版本、发布包名称与 SHA-256、升级规则、历史版本
统一包/                        框架本体（新项目复制这一个目录里的全部内容，含隐藏目录）
```

发布页（Releases）另附同内容的 ZIP 与 `.sha256`，供下载安装和核对。ZIP 解压后就是 `统一包/` 文件夹。

## 环境

- 必需：Python 3.9+；涉及存档仓库的检查需要 Git。
- 可选：Chrome（设计截图）、Pillow（像素辅助脚本）。
- 在 macOS 上做过完整检查与独立核对；其他系统没有验证过。
- 软件登录、联网、浏览器工具、发布平台的账号与授权由你自己的环境提供，装上本框架不等于已经连通。

## 边界

- 提交前检查只是常见格式的密钥扫描，不保证识别一切凭据；它也不是不可绕过的安全系统。
- 同一个项目文件夹同一时间只让一个对话修改。
- 本仓库按维护者授权公开，不含访问凭据、客户数据或项目记录；未默认授予第三方额外的开源许可。
