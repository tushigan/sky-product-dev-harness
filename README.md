# SKY 产品开发经理（Codex / Claude Code 统一包）

**当前版本：v6.1.2 ｜ 发布日期：2026-10-11 ｜ 需要 Python 3.9+**

这是一套给 AI 编程助手（Codex 或 Claude Code）用的“产品开发框架”。装进一个项目文件夹后，助手会扮演一位产品经理，带着一个有想法、但没做过产品的人，把产品一步步做出来：先把需求问清楚写成文档，有界面就画几版设计稿让你选，再排成一个个阶段开发，每个阶段做完先自己检查一遍再给你看，最后按你的需要发布上线。顺序不是死的，中途加功能、改主意、先发一版给朋友看都可以。

- **给谁用**：想做一个网站、桌面软件、手机应用、命令行工具，或者规则与技能包这类本地文件包，但不懂技术的人；也适合想让 AI 按固定流程、留好文档和交接记录来开发的人。
- **它是什么**：一个文件夹，里面是规则（`AGENTS.md`）、6 个环节技能（拷问需求、设计、计划、开发、复核、发布）、2 个帮手（只读审查员、上网查证的探路员）和几个检查脚本。Codex 和 Claude Code 共用同一个文件夹，可以交替接着做。
- **它不是什么**：不是网页系统，不需要服务器、账号或密钥；不是给 Claude 网页聊天用的插件；包里不带任何具体项目的资料。

## 新项目：复制下面一段给你的 Agent

先建一个空文件夹作为新项目（或者选好要放的位置），在 Codex 或 Claude Code 里打开它，把下面这段整段贴进对话：

```text
请从 https://github.com/tushigan/sky-product-dev-harness 安装“SKY 产品开发经理”开发框架到当前文件夹。
1. 先读取仓库根目录的《版本清单.json》，确认最新版本号、发布包下载地址和 SHA-256。
2. 从发布页下载清单里写的 ZIP，算 SHA-256，与清单一致才继续；不一致就停下告诉我，不要用。
3. 解压到项目外的临时目录，把其中“统一包”文件夹里的全部内容（包括 .agents、.claude、.codex 这三个隐藏目录）复制到当前文件夹根目录。当前文件夹里如果已经有 AGENTS.md、CLAUDE.md、.claude/、.agents/、.codex/ 或其他同名文件，先停下告诉我，不要覆盖。
4. 在当前文件夹运行 python3 工具/维护.py check 和 python3 测试/框架回归.py，把实际结果告诉我。没有 Python 就直说需要安装 Python 3.9 以上，不要声称检查已通过。
5. 不要安装付费或需要账号的东西；缺什么环境如实列出。
6. 完成后告诉我：装好的版本、检查结果，以及我需要重新打开对话才能让技能生效（如果需要的话）。
```

装好后重新打开这个文件夹的对话，直接说“我想做……”就可以开始。

## 已有项目：从 6.1.1 升级到 6.1.2

已有项目里你的需求文档、设计规范、开发计划、项目交接记录和代码都不用动，升级只换框架部分。在**该项目文件夹**里新开一个对话，把下面这段整段贴进去：

```text
请把本项目的开发框架升级到 https://github.com/tushigan/sky-product-dev-harness 发布的最新版。
0. 判断版本：先读取仓库根目录的《版本清单.json》，再读本项目根目录的 版本.json 里的“版本”。
   - 本项目已经是清单里的最新版本，且 python3 工具/维护.py check 通过：告诉我不用升级，到此为止。
   - 本项目是 6.1.1：按下面 1—9 步做。
   - 没有 版本.json，或是 6.1.1 以外的其他版本：停下告诉我现在是什么情况，不要动任何文件。
1. 把整个项目文件夹完整备份到项目外面（同级目录，名字带“升级前备份-v6.1.1-日期”），核对备份文件数与原文件夹一致再继续。
2. 从发布页下载清单里写的 ZIP，算 SHA-256，与清单一致才继续；解压到项目外的临时目录（下面“新包”指其中的 统一包/ 文件夹）。
3. 维护源：先把本项目的 维护源/生成清单.json 复制到项目外暂存；用新包的 维护源/ 替换本项目的 维护源/；再把暂存的旧 生成清单.json 放回 维护源/（必须用项目原来的这份，用新包里的会让检查误报“生成文件被单独修改”）。如果本项目改过维护源里的内容，先对照差异合并，不要直接覆盖。
4. 脚本：逐个替换这三个文件，不要整个文件夹覆盖（项目里 工具/、测试/ 下可能有自己的文件）：工具/维护.py、工具/提交检查.py、测试/框架回归.py。
5. 根目录两个文件：用新包的 版本.json、使用说明.md 替换。
6. 说明/：要么把新包 说明/ 下的全部文件都复制过来（版本记录.md、验收结果.md、适配依据.md、6.1.1改动计划.md、Claude发现结果.json、Codex发现结果.json），要么一个都不复制，不要只换其中几个。建议全复制。
7. 在项目根目录运行 python3 工具/维护.py sync，再运行 python3 工具/维护.py check 和 python3 测试/框架回归.py，全部通过才算升级完成。如果检查提示“生成文件被单独修改”，说明之前有人直接改过生成出来的技能文件，先把那些改动合并回 维护源/，再重跑。
8. 若项目里已有 项目交接.md，按新的 维护源/项目交接模板.md 把它整理成上半“给用户”、下半“技术附录（给 Agent）”，原有内容放进技术附录，不删。
9. 需求文档、设计规范、开发计划和产品代码一个字都不要改。不要推送、不要发布。完成后用三段白话告诉我：做了什么、对我有什么影响、要我做什么；检查的实际结果写进项目交接的技术附录。
```

以后仓库发了新版本，再贴一次同一段，Agent 会比对版本清单，判断要不要升级。

## 6.1.2 改了什么（白话）

- **跟你说话更好懂**：汇报和总结分三段——做了什么、对你有什么影响、要你做什么；正文里不夹命令、程序名和英文术语；要你复制的东西放在单独的框里，并说明贴到哪里。
- **交给另一个 Agent 接着做时三样一起给**：写好的提示词文件、一段能直接复制的短提示词、建议用什么模型和多高的思考等级。
- **可以“自动接力”**：软件支持在背后派助手时，Agent 可以提议让助手做完一批、另一个助手核对、通过再做下一批；只有你同意才这样做，遇到要你拍板、上线、花钱、对外发消息、删文件时会停下来。
- **项目交接记录分成上下两半**：上半给你看，下半是给 Agent 的技术附录。
- 自带回归检查从 16 项增加到 17 项；修了一个 6.1.1 就有的老问题：项目里已经建好存档仓库、装好提交前检查时，回归检查以前必然有 1 项不过，现在都能全过。

完整版本记录见 [统一包/说明/版本记录.md](统一包/说明/版本记录.md)，包内使用说明见 [统一包/使用说明.md](统一包/使用说明.md)。

## 仓库里有什么

```text
README.md        本页
版本清单.json    当前版本、发布包名称与 SHA-256、历史版本
统一包/          框架本体（新项目复制这一个目录里的全部内容，含隐藏目录）
```

发布页（Releases）另附同内容的 ZIP 与 `.sha256`，供下载安装和核对。ZIP 解压后就是 `统一包/` 文件夹。

## 环境

- 必需：Python 3.9+；涉及存档仓库的检查需要 Git。
- 可选：Chrome（设计截图）、Pillow（像素辅助脚本）。
- 在 macOS 上做过完整检查与独立核对；其他系统没有验证过。
- 软件登录、联网、浏览器工具、发布平台的账号与授权由你自己的环境提供，装上本框架不等于已经连通。

## 边界

- 提交前检查只是常见格式的密钥扫描，不保证识别一切凭据；它也不是不可绕过的安全系统。
- 同一个项目文件夹同一时间只让一个对话修改。
- 本仓库按维护者授权公开，不含访问凭据、客户数据或项目记录；未默认授予第三方额外的开源许可。
