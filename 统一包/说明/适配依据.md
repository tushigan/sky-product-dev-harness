核对日期：2026-10-01（Asia/Tokyo）。实际本机版本：Codex CLI 0.154.0；Claude Code 2.1.284。更旧版本及其他操作系统未实测。

官方来源：
- Codex 技能目录与发现规则：https://developers.openai.com/codex/skills/

采用项目级标准入口，不依赖全局配置。Claude 根入口使用 @AGENTS.md 引用，Codex 根入口直接承载共同规则。技能的描述允许按自然语言自动选择，实际选择效果仍取决于宿主和任务。

原两套各 27 个技能资源文件，其中 25 个字节相同。六阶段工作流、模板、设计素材与辅助脚本被保留；改动集中在命名、宿主路径、工具缺失处理、授权边界与项目交接。两个宿主的技能副本由脚本产生，平时只维护一个源。

原截图脚本为 macOS/Linux Chrome 辅助工具，并非跨操作系统浏览器驱动；页面视觉检查仍由当前可用工具执行。不将复制成功、发现技能成功等同于完成真实产品开发验收。

## 6.2 开发循环的宿主依据（2026-10-19 查证，探路员报告）
- Claude Code：子代理定义文件可写 model（sonnet / opus / haiku / fable / 完整编号 / inherit）与 effort（low–max，视模型）；主代理派子代理时可临时传 model 与 effort，优先于定义文件（effort 临时参数需 2.1.292 及以上；环境变量 CLAUDE_CODE_EFFORT_LEVEL 高于两者）。出处：https://code.claude.com/docs/en/sub-agents
- Codex：自定义子代理文件可写 model、model_reasoning_effort；文件里写了则以文件为准。派生工具 spawn_agent 带 model、reasoning_effort 参数，但受内部开关控制，个别版本或账号可能不暴露，须现场试。子代理沙箱与审批一律继承父会话，定义文件里写 sandbox_mode 不生效；执行子代理要写文件，父会话须为 workspace-write。思考等级取值 low / medium / high / xhigh / max / ultra，视模型与客户端。出处：https://learn.chatgpt.com/docs/agent-configuration/subagents （原 developers.openai.com/codex/subagents 跳转）、https://learn.chatgpt.com/docs/models 、https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs
- 因此规则只规定“档位派活时指定、不写进定义文件、模型名开工前现查”，包里不写死模型名。
- 未验证：Codex 实跑派生指定模型；Codex 下 sky-reviewer 定义里的只读设定实际不构成只读沙箱（6.1.x 起即如此，本版未改，列为后续建议）。
