## 6.3 · 2026-10-20
- 起因：一个 Harness 项目里，用户说“三批都改”“16 项全做”后，Agent 没写需求文档和开发计划、没问开发循环就直接改，还在项目交接里自写“开发循环：未涉及”；收到用户转来的停下指示后仍继续改。用户 2026-10-20 拍板（原话）：“對，這些都補上，然後升級成新版本的空包給我”。
- 新增 [动手改产品之前 · 三道门]（放在规则最前面）：不分大小、不分有没有界面，动第一个产品文件前确认需求清单有行、开发计划有阶段和验收条件、“开发循环”一行已填用户回答；用户说“改/都改/全做”或批准改动清单都算进入开发；项目里另一套规则是产品内容，管 Agent 的始终是本文件；改到一半才发现就做完手上一步停下补门。
- [开发循环] 开工前确认不再只挂在 sky-build：直接改产品文件同样触发；“开发循环”一行只记用户回答或宿主派不了这一事实，禁止 Agent 自填“未涉及”“不适用”。开发计划模板、项目交接模板同步注明。
- [做事的规矩] 新增叫停即停：用户直接说或从另一个会话转来的停下指示，做完手上这一步就停，记进项目交接；压缩时保留未照办的停下指示。
- sky-grill、sky-build 的触发说明补上“按资料或经验优化产品”“改/都改/全做/批准改动”；[技能] 列表同步。
- 提交检查加三道门提醒：暂存里有产品文件、三道门有缺口时提示，不阻止提交；`--流程` 不需要 Git 仓库即可自查。没有用宿主 hook：本包把宿主 hook 视为待人工核实的旧配置，两边也不对等。
- 回归增至 22 项：新增三道门规则存在性、提交时只提醒不阻止、`--流程` 自查、提醒边界用例四项。

## 6.2 · 2026-10-19
- 新增 [开发循环]：把用户在多个项目里反复手动交代的做法写成框架自带规则。主 Agent 只规划和审核，每批代码派新的执行子代理写；审不过派新子代理只修审出的问题；便宜档首次 + 返修两次，返修第 3 次换聪明档，再不过停下问用户是否开更高思考深度或换模型；换名、拆批、换子代理不重置次数，环境/权限/登录/额度阻挡不算返修。
- 开工前确认：第一次进入开发前问用户开不开，并建议便宜档、聪明档（模型 + 思考深度，可为区间），用户确认或自改，原话记进开发计划约定；可随时开、关、换档。用户 2026-10-19 拍板：返修阶梯取“便宜档两次 → 聪明档一次 → 问用户”；阶段通过后自动跑完全部阶段；开不开由开工前确认决定；两档由用户自选、Agent 可先建议。
- 旧“自动接力”并入开发循环；手动交给另一个 Agent 的“三样一起给”保留，只在循环没开时用“退回两次提醒调高一档”。
- sky-build 新增开工前确认、派工单写法；sky-review 在循环开着时把问题转返修阶梯、阶段间不停等用户；开发计划模板约定加“开发循环”一行；项目交接模板加循环状态一行；共享文件夹加 派工/。
- 回归增至18项：新增开发循环规则与模板存在性检查；原第17项关键词随“自动接力”并入同步调整。
- 返修（第一次独立核对未通过：2 项必修、10 项建议，同日全改）：执行子代理身份与自身停止条件写进规则和派工单；阶梯用完后用户批准升级，每多一轮都要重新点头；全盘复核单独计批、拆批时问题记在所在批；文档状态只由主 Agent 审核后改，“已验证”只在复核技能通过后打；复核里有要拍板的事必停、留待项在进展句里说出；“暂不开”也记录；不能派子代理与派不了指定模型分开处理；开发以外的分批活可同法循环；Codex 定义文件优先的事实更正；使用说明补白话与授权说法；回归去重并补“循环不跳过复核”守护。
