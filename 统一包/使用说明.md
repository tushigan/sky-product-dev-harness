# SKY 产品开发经理 6.2 · Codex / Claude Code 统一包

## 直接怎么用

1. 把整个“统一包”文件夹复制到你的工作区，重命名为这次项目的名字。每个项目复制一份。
2. 在 Codex 或 Claude Code 中打开这个文件夹本身；打开后应能在根目录看到 AGENTS.md、CLAUDE.md、工具/。不要只打开里面的代码子文件夹。
3. 新开会话，直接说“我想做……”或“继续这个项目”。首次软件要求信任文件夹时，由你正常确认。
4. 换工具时，先结束上一边的修改，再在另一边打开同一个文件夹，说“读取项目交接，继续开发”。

Agent 汇报和总结时按三段说：做了什么、对你有什么影响、要你做什么（向你提问和新项目开场时不套三段，已有项目接着做时报进度照样分三段）；不夹命令和英文术语，网站名、产品名和画面上照原样显示的字会加引号照写并附一句白话，要你复制的东西会放在框里并说明贴到哪里。交给另一个 Agent 接着做时，它会给你提示词文件、一段能直接复制的短提示词和模型建议。

开发循环（6.2 新增）：开始写代码前，Agent 会问你要不要开“开发循环”，并建议两档——便宜档（平时写代码和前两次返修用）、聪明档（返修两次还不过时用），每档是一个模型加一个思考深度，你可以照建议，也可以自己改。开了以后，Agent 自己只做规划和检查，代码交给它在背后派出的帮手写；检查不过就派帮手返修，便宜档修两次不过换聪明档再修一次，还不过才来问你要不要开更深的思考或换更强的模型；一个阶段检查通过就接着做下一个，直到全部做完、全盘检查过再交给你。要上线、推送（把存档备份到网上）、花钱、对外发消息、删你的文件或要你登录时照样先停下问你（你之前已经同意过的照旧办）；你定了要开更深的思考或换模型后，它每多修一轮（或你说定的那几轮）用完都会再问你。随时可以说“关掉开发循环”或“换档”。软件关掉后它不会在后台继续，下次打开说“继续开发”会从记录的地方接着做。

无需先运行安装命令，也不用全局安装技能。入口与技能已经随包生成。隐藏的 .agents、.claude、.codex 目录必须一起复制；最稳妥的方式是复制整个文件夹，或解压完整压缩包。复制进去后已有会话可能需要重新打开。

这是给 Codex 与 Claude Code 的项目包，不是给 Claude 网页聊天或 Cowork 的通用插件。软件登录、联网、浏览器工具、Python 和项目依赖仍由实际环境提供。管理策略禁用项目技能或不信任目录时，包不能绕过限制。

## 两边能接上什么

产品需求文档、设计规范、开发计划、项目交接记录和代码共用。聊天历史、账号登录、浏览器连接、权限和后台进程不会自动同步。两边交替使用同一目录；不要让两个会话同时改同一份文件。

六个阶段保留：拷问需求、设计、计划、开发、复核、发布。正常用中文说需求即可。需要点名时：Codex 用 `$sky-grill` 等，Claude Code 用 `/sky-grill` 等；其余为 sky-design、sky-plan、sky-build、sky-review、sky-release。

## 检查与维护

以下工作由 Agent 做即可，不要求你记命令。运行脚本需要 Python 3.9+；涉及 Git 的检查需要 Git；原设计截图工具还需要 Chrome，像素辅助脚本需要 Pillow。

- `python3 测试/框架回归.py`：在临时目录复查18项框架行为（含新规则是否进了入口），不操作项目业务资料。
- `python3 工具/维护.py check`：核对版本、共同源、两边生成内容及旧框架入口和hook残留。
- 修改工作流时，只改 维护源/，再执行 `python3 工具/维护.py sync`。若有人直接改过生成文件，会拒绝覆盖，先人工合并。
- 每次提交前运行 `python3 工具/提交检查.py`。它检查暂存内容，不打印疑似密钥；扫描只是常见格式检查，不保证识别一切凭据。
- 项目根目录建好 Git 仓库后运行 `python3 工具/维护.py install-hook`，使正常 Git 提交自动调用共同检查。若已有 hook 或 hooksPath，保留原设置，由 Agent 查明后接入，不能覆盖。
- 类型检查只运行根目录及三层子目录内 package.json 已声明的 typecheck 脚本，不下载工具；其他语言、深层项目和没有脚本的项目按开发计划补充验证。

已有项目迁入时：先在项目外完整备份；保留业务需求、计划、调研及代码；核实并移出旧 .claude/CLAUDE.md、旧宿主hook及旧技能/帮手，合并必要的自定义配置；再放入新框架、运行 check 并建立项目交接。检查不会自动删除配置。含自定义hook的配置会要求人工核实；不会仅因JSON合法就放行。这个包首先用于新项目。

版本以根目录 版本.json 为准，当前为6.2；外层目录和新压缩包同号，历史版本单独保留。

## 结构

- AGENTS.md：共同项目规则，Codex 直接读取。
- CLAUDE.md：引入同一份 AGENTS.md，Claude Code 读取。
- .agents/skills/、.claude/skills/：由同一份源生成的完整技能，使用普通文件，避免复制时符号链接失效。
- .codex/agents/、.claude/agents/：两边的审查员和探路员定义。
- 维护源/：规则、技能、帮手及原有设计素材的唯一维护来源。
- 派工/：开发循环开着时，派给帮手的派工单放这里（开始开发后才会有）。
- 工具/：一致性检查、生成和共同提交检查。

没有捆绑个人绝对路径、账号凭据、固定模型或默认发布目标；开发循环的模型由你每个项目自己定。原版附带的宿主提交事件配置没有直接沿用，改为两边共用 Git 检查及提交前显式检查，避免把特定宿主事件格式当成通用能力。

验证范围见 说明/验收结果.md。
