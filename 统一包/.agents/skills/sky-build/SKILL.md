[任务]
    按开发计划把产品做出来。一个阶段做完再做下一个；每个阶段做完，需求清单的"已实现"打勾。

[前置]
    开发计划写好。做某个阶段之前，先把它验收自的那几条需求和涉及的设计稿原文读一遍，不凭记忆。

[开工前确认开发循环]
    进入开发时（含开发到一半、刚升级到本版的项目，也含只改几行规则或文字的小改），看开发计划约定里“开发循环”一行填了没有。这一行只记用户的回答，不自己填“未涉及”“不适用”。没填，且宿主能派子代理时，按 AGENTS.md 的 [开发循环] 问用户要不要开，并给出便宜档、聪明档的建议（模型和思考深度），他确认或改了再记进约定。他不想现在定，就记“暂不开，用户说以后再定”加日期，照下面的做法自己写，之后不每次再问。
    开着时：主 Agent 不写产品代码，下面 [第 0 阶段] 到 [阶段结束] 的活由执行子代理按派工单做，主 Agent 审核、按返修阶梯派返修、过了接着派下一阶段，一路做完全部阶段。要对用户说的话（如第 0 阶段讲存档、请他登录或授权）由主 Agent 说，子代理不直接找用户。下面 [每个阶段] 里“同一个错修了三次就停”换成返修阶梯。
    关着时：照下面的做法由主 Agent 自己做。

[第 0 阶段：搭骨架和仓库]
    骨架按开发计划里第 0 阶段的定义搭。
    建仓库前用一句人话讲清存档是怎么回事：每提交一次就是一个存档点，随时能回到那一刻；推送是把存档备份到网上的代码仓库（如「GitHub」，一个存代码的网站）。讲这一次就够，以后每次提交只说一句"存了一个档"，不报提交号。
    本机仓库一定建，不需要账号。用户明确授权云端备份后才建私有仓库推上去，登录要他自己在浏览器里做；没有账号就先只在本机提交，告诉他想备份到云端时再说。仓库地址记进开发计划的约定。

[每个阶段]
    改界面前先读设计规范和组件清单，能复用的复用，不另造一套。
    没 key 的按开发计划里写的，用固定数据代替外部服务的返回，接口保留；凭据可用且有真实调用授权后才换成真实服务。
    不做假功能：每个按钮、设置项、快捷键都真的接上；做不了的功能不留能点的东西。
    同一个错修了三次还在（开发循环开着时按它的返修阶梯），停下来告诉用户，不无限试；按 AGENTS.md 的 [对用户说话] 说卡在哪、影响什么、要他定什么，报错原文写进开发计划或项目交接的技术附录。

[测试]
    测试用例的名字直接用验收条件那句 Given / When / Then，看名字就知道对应哪条。
    只写这个阶段验收要的测试，不硬凑。测试不碰用户的真数据和真凭证，用临时目录。

[阶段结束]
    按开发计划运行适用的测试和检查，看退出码，不看最后几行。Python或Harness文本产品按其脚本、规则和行为验收；没有类型检查的标不适用，不冒充通过。
    把产品跑起来，按这个阶段的验收条件快速过一遍；完整的验证在复核时做。
    需求清单"已实现"打勾，开发计划这一行改状态。
    提交前运行 `python3 工具/提交检查.py`（从项目根目录运行），非零退出时先修复，不绕过。提交后，仅已有明确推送授权时推送；否则只提交。按实际结果报告：仅本地提交说"已在本机存档，未推送"；确认推送成功才说"已存档并推送"；失败说明失败，不冒充成功。
    写进文档和提交说明的日期取本机当前时间，不凭记忆。

[派工单怎么写（开发循环开着时）]
    一批一个文件，放项目根目录 派工/，文件名写阶段、批次和第几次返修（如“第3阶段-第1批-返修2”）。
    写清：这批做什么；验收自哪几条需求，原文抄 Given / When / Then；要先读的文件（需求、设计规范、设计稿、相关代码）；不许动的地方；做完怎么自测、要回报什么（改了哪些文件、跑了什么、结果、没做完的）；按本技能的 [测试] 和 [阶段结束] 本机提交，不推送。
    返修单只附原派工单和这次审出来的问题（带文件、行号或能重现的步骤），写明只修这些。
    派工单开头写明执行子代理的身份：你只做这一批，做完回报就停；不走开发循环、不再派子代理、不接着做下一批或下一阶段；不改需求清单、开发计划、项目交接（这些由主 Agent 审核后改，本技能 [阶段结束] 里改文档那几句对你不适用）；不直接问用户，需要用户的事写进回报后停；同一个错在这一轮修三次还在就停，写进回报。
    派的时候写明用哪档、挑的思考深度和理由。

[完成标准]
    这个阶段验收自的每条 Given / When / Then 都能当场演示；测试全过；已提交；需求清单和开发计划都改了。开发循环开着时，再加：审核方核过，这一批的档位和返修次数记进了项目交接。

[跨环境续接]
    开始时读取项目根目录 AGENTS.md 的环境适配与交接规则。阶段结束更新同一份开发计划和项目交接.md；不得把作者自测写成独立复核。相对资源路径均相对于当前加载的本技能目录。
